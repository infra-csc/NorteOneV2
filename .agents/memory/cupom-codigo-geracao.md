---
name: Coupon codes are pasted, not generated
description: Cortesia cupom codes are pasted in from Magento, not auto-generated by the app (reversed 2026-08) — read before touching gerar_cupom or anything that assumes system-generated codes.
---

As of 2026-08 the app no longer generates cortesia coupon codes itself — that direction was reversed. The old sigla+SKU+random-suffix generator (fixed total length, worst-case-prefix sizing, combinatorial space preflight) was removed entirely, along with the requirement that an area have a sigla or an event have a SKU. The flow is now: someone creates the code(s) manually in Magento, then pastes them into `gerar_cupom` (`POST /{solicitacao_id}/gerar`), which only validates and stores what was pasted:
- Number of pasted codes must exactly equal `sol.quantidade` (no partial fulfillment).
- Duplicate check is case-insensitive, both within the same paste and against every other solicitação (the global `ux_cortesia_cupom_codigo_codigo` unique index is still the source of truth for cross-request uniqueness).
- Codes are stored exactly as pasted, not forced to uppercase — Magento redemption may be case-sensitive.
- Sigla (area) and SKU (event) are **no longer required** to mark a solicitação as generated. Don't reintroduce that requirement.

**IntegrityError-on-commit handling:** when a caught `IntegrityError` at commit time is converted into a friendly response, check which constraint actually fired (string-match the unique index name against the exception) before treating it as "just a conflict, 409 it." A blanket catch-all risks masking a real, unrelated bug as a fake duplicate-code conflict. There's nothing to retry/regenerate here (the code came from a human, not the app), so any other integrity error must surface as a real 500, not a silent retry loop.

**Why this matters:** other previously-proposed features (bulk-generating codes from the pending-request queue, warnings about remaining "code space") assumed the app still generates codes and are now built on a premise that no longer holds — check whether they're still wanted (and re-scope them to "bulk-paste" rather than "bulk-generate") before implementing.

**Unrelated but adjacent fact:** the area create/edit UI (projection settings) has no sigla field anymore — removed at the user's request. `AreaProjecaoCreate.sigla` is optional and the dedicated `PUT /areas/{id}/sigla` endpoint is still live, just UI-less. This no longer blocks coupon generation (see above), but any other sigla-dependent feature should know areas can exist with `sigla=NULL`.
